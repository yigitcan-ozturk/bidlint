# BidLint Pilot Success Metrics

The early-adopter phase is evaluated on user evidence, not vanity metrics.

## Primary targets

- 5 real practitioners who install or run BidLint
- 3 substantive feedback reports
- 1 sanitized external case study
- 1 external contribution, reproducible issue or integration request

## Secondary signals

- GitHub stars and watches
- repository clones / installs when measurable
- LinkedIn comments or direct messages from relevant practitioners
- repeat usage by the same practitioner

## What counts as substantive feedback?

Feedback should identify at least one of:

- incorrect or unsafe finding
- terminology / unit / evidence edge case
- workflow friction that matters in production
- missing procurement hand-off requirement
- feature request grounded in an actual technical evaluation workflow
- confirmation that a specific workflow was materially easier to review

## What does not count by itself?

- likes
- generic compliments
- stars without usage evidence
- feature ideas with no real workflow context

## Release discipline

Do not expand the feature surface solely to increase attention. Prioritize changes that are supported by reproducible real-user evidence and preserve deterministic evaluation, provenance and explicit uncertainty.
