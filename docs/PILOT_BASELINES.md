# Pilot baselines

BidLint 1.1 pilot evidence can be retained as an immutable approved baseline and compared with evidence produced by a later 1.x build.

The workflow is intentionally two-step:

```bash
bidlint-pilot pilot.json --json --output current-evidence.json
bidlint-pilot-verify approved-baseline.json current-evidence.json
```

Use `--json` on the verifier when the result will be consumed by CI or another automation:

```bash
bidlint-pilot-verify approved-baseline.json current-evidence.json --json
```

## What must match

A baseline replay requires the following evidence fields to remain equal:

- `pilot_id`;
- compare/rank `mode`;
- `report_count`;
- manifest SHA-256 digest;
- corpus SHA-256 digest;
- deterministic output SHA-256 digest.

The current evidence must also remain `passed`, `deterministic` and `conformant`.

The repeat count is deliberately not frozen. A current replay may use more repetitions than the approved baseline as long as the corpus, manifest and resulting deterministic output are unchanged.

## Why corpus and output are separate

A changed corpus digest means the inputs or referenced policy files changed. A changed output digest with an unchanged corpus and manifest means BidLint behavior changed for the same declared pilot. Keeping these conditions separate makes upgrade review explicit instead of silently replacing the baseline.

## Baseline eligibility

A baseline is accepted only when it was itself generated by `bidlint-pilot` and records:

- `passed: true`;
- `deterministic: true`;
- `conformant: true`.

An unsuccessful pilot cannot be promoted into an approved baseline merely to make future replays match it.

## Exit codes

`bidlint-pilot-verify` returns:

- `0` when baseline and current evidence match;
- `3` when evidence is invalid or the replay mismatches;
- `5` when an evidence file cannot be read;
- argparse's `2` for invalid command usage.

A mismatch is evidence requiring review. It is not automatically classified as a regression: an intentional backward-compatible change may legitimately produce a new output, but that change must be reviewed and a new baseline explicitly approved.

## External pilot boundary

Synthetic tests and baseline tooling do not satisfy the v1.1 external-pilot roadmap gate. That item closes only after a real external corpus has been sanitized, executed, technically reviewed, and any discovered defects have been converted into regression fixtures.
