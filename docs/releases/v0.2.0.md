# bidlint v0.2.0

**Real-world deterministic engineering workflow.**

v0.2.0 moves `bidlint` beyond the initial specification-vs-submittal core and adds the engineering normalization, vendor parsing and multi-vendor reporting needed for practical technical bid evaluation.

## Highlights

### Engineering unit conversion

Supported values can now be compared across explicit units in the same physical dimension:

- power: `W`, `kW`, `MW`
- pressure: `Pa`, `kPa`, `MPa`, `bar`
- length: `mm`, `cm`, `m`
- flow: `L/s`, `L/min`, `m³/s`, `m³/h`

Example:

```text
Required: >= 10 kW
Offered : 10000 W
Result  : PASS — 10000w (= 10kw)
```

Unknown, missing or dimensionally incompatible units remain `REVIEW` instead of being guessed.

### More realistic vendor datasheet parsing

`bidlint` now recognizes conservative, explicit vendor layouts including:

```text
Motor power: 11 kW
```

```text
Motor power        11 kW
Design pressure    10 bar
```

```text
Motor power
11000 W
```

```text
Housing material:
316L stainless steel
```

Descriptive material grades such as `316L stainless steel` remain qualitative and are not misread as the numeric value `316`.

### Engineering terminology aliases

A conservative built-in terminology layer normalizes low-risk nomenclature variants before fuzzy matching.

Project- and vendor-specific terminology can be supplied explicitly:

```json
{
  "rated output": "motor power",
  "supplier ip code": "ip rating"
}
```

```bash
bidlint compare specification.pdf vendor.pdf --aliases aliases.json
```

Ambiguous concepts are deliberately not collapsed automatically. For example, `protection class` is not treated as equivalent to `ip rating`.

### Multi-vendor technical bid tabulation

`rank` now produces more than terminal ranking and JSON.

Generate a self-contained HTML technical tabulation:

```bash
bidlint rank specification.pdf vendor-a.pdf vendor-b.pdf \
  --output technical-tabulation.html
```

The report includes:

- deterministic vendor ranking
- compliance score and status counts
- requirement-by-vendor matrix
- offered values
- deterministic decision reasons

Export a long-form CSV for spreadsheet and procurement workflows:

```bash
bidlint rank specification.pdf vendor-a.pdf vendor-b.pdf \
  --output technical-tabulation.csv
```

## Decision model

The core principle remains unchanged:

> **Evidence before confidence.**

`PASS` and `DEVIATION` are used only when the comparison can be made deterministically. Missing, qualitative, ambiguous or unsupported evidence remains visible as `MISSING` or `REVIEW`.

The deterministic core runs locally and does not require an LLM or external API.

## Upgrade from v0.1.0

No migration is required for the existing CLI workflow.

Existing commands remain valid:

```bash
bidlint compare specification.pdf vendor.pdf
bidlint rank specification.pdf vendor-a.pdf vendor-b.pdf
```

v0.2.0 adds new parsing behavior, unit-safe comparison, custom terminology aliases, and HTML/CSV batch outputs.

## Current limits

- text-based PDFs only; OCR is not included
- arbitrary PDF table-cell reconstruction is not yet implemented
- complex visual multi-column layouts may need preprocessing
- unit conversion is limited to documented deterministic families
- qualitative requirements remain `REVIEW` unless an explicit deterministic rule exists

These limits are surfaced intentionally rather than hidden behind a confidence score.

## Validation

The v0.2 development line was regression-tested across the new unit, parsing, terminology and portfolio-reporting paths, with **31 tests passing** before release freeze. Package build and real bundled-sample HTML/CSV generation were also validated.

## Next

v0.2.x will focus on document coverage and hardening. Later milestones include optional AI-assisted structured extraction, MCP, IFC inputs and integration with the broader explainable procurement toolchain.
